How it works

Three ways to switch, one click to do it.

Every program keeps its sign-in somewhere on disk or in the OS keychain. An app definition says where, and Profile Manager picks the right strategy for it.

01

Swap

Captures the files, folders, JSON keys and keychain entries that hold the sign-in into an encrypted snapshot, and restores another profile's snapshot in their place.

Wrangler · Claude Code · AWS · Slack
02

Native

For programs that already support several accounts, it calls their own profile commands.

gh auth switch · kubectl config use-context
03

Per-command

Decrypts a profile into a private temporary folder, points the program at it, saves changes when it exits and wipes the folder. Two accounts in two terminals at once.

profilemanager exec · shell
# the same binary is a command-line tool
$ profilemanager add wrangler Work            # save the current sign-in
$ profilemanager switch wrangler Personal     # --quit closes a running app first
$ profilemanager exec wrangler Work -- wrangler deploy
$ profilemanager shell claude-code Work       # a shell signed in to Work

Security & safety

Your tokens stay sealed, and switches can't half-happen.

  • Save before switchingThe live sign-in is saved into the active profile before another is restored, and auto-sync (every 30 s by default) keeps rotating OAuth tokens current.
  • Account-mismatch checkIf someone signed in to a different account, it isn't written over your profile. You choose: keep it as a new profile, update, or restore.
  • Waits for running programsElectron apps and Claude Code sessions are switched once they close, or asked to quit cleanly.
  • Atomic, with rollbackFiles are replaced by write-then-rename and folders swapped in whole. If any step fails, the previous sign-in is put back.
  • Dotfile links intactSymlinks such as ~/.npmrc → dotfiles/npmrc are written through, not replaced.

AES-256-GCM vault

Each snapshot is bound to its app and profile, so a file swapped or edited on disk fails authentication. The random 256-bit master key never sits next to the vault: it lives in your OS credential store.

Privacy policy

Nothing leaves your computer.

Profile Manager has no accounts, no analytics, no ads and no crash reporting. It makes no network connections of its own and sends nothing to its developer or anyone else.

What it stores, and where

  • Saved sign-ins (snapshots of other programs' sign-in files and keychain entries), sealed with AES-256-GCM, in its data folder: ProfileManager in your user config folder, or PROFILE_MANAGER_HOME if you set it. A rollback copy of the sign-in from just before the last switch is kept there too, sealed the same way.
  • The vault's master key in your system's credential store (macOS Keychain, Windows Credential Manager, Linux Secret Service), or in a private vault.key file in the data folder when there is no credential store.
  • Settings and state (state.json): profile names, which profile is active, and fingerprints of files. No passwords or tokens.
  • Your own app definitions, as JSON files in the data folder.

What it reads and changes on your computer

  • The sign-in files, folders and keychain entries named by the definitions of apps you save profiles for, so it can save and restore them. Auto-sync checks them on a timer (every 30 seconds by default) while the app runs.
  • The list of running programs, to see whether an app it switches is open; with your choice, it asks that app to quit.
  • Programs' own profile commands (such as gh auth switch or kubectl config use-context) for apps switched natively, and the commands you run with profilemanager exec or shell. Those programs talk to their own services as they always do; Profile Manager doesn't see or forward that traffic.

What it sends

Nothing. The only time it opens anything online is when you click a link, such as an app's documentation, which opens in your browser.

Deleting your data

Deleting a profile in the window removes its snapshot. Deleting the data folder removes everything the app saved; uninstalling the app alone leaves it in place (except the Microsoft Store version, which Windows removes with the app). The master key can then be removed from your credential store, where it is the entry for com.xmhrnx.profilemanager.
